# Changelog

## Unreleased

- Breaking, CLI: every command follows the [command-line conventions](docs/development.md#command-line-conventions), with no aliases. `wye init --out <path>` is `wye init -c <path>`; without it, `init` writes the config `$WYE_CONFIG` names, else `~/.wye/wye.toml`, as every command reads. `wye explain --token-file` defaults to the token in `$WYE_TOKEN`, as `wye claude` and `wye codex` do. `wye service uninstall` shows what it stops, removes, and keeps, and asks first (`-y` skips the question, `--dry-run` only shows). Exit status: wrong usage exits 2 instead of 1 (an unknown command or option, a missing argument, a value a command cannot read such as `--ttl 1w`, or `service install` or `uninstall` without a terminal or `-y`); `doctor` and `policy-test` exit 1 instead of 3 when they find problems, as does `service status` for a service that does not answer; 3 now means done, with something to act on (a refusal from `explain`, widened access from `policy-diff`, nothing installed for `service status`). Streams: `wye init` prints what it wrote and the next steps on stderr, `wye token keygen` prints only the `signing_keys` line on stdout, and `wye service` prints its progress and question on stderr, keeping stdout for the plan.
- Each flag that several commands take reads the same in all their help (`-c`, `--url`, `--token-file`, `-y`, `--dry-run`, and how a duration is written), and defaults name `$WYE_HOME` rather than `~/.wye`.

- `wye serve --usage-log <path>` appends usage records to that file instead of stdout, creating it with mode 600. At 64 MiB the gateway renames it beside itself with the UTC time (`usage-20261107T091500Z.jsonl`) and starts a new one; a record never spans two files, and rotated files are never deleted. Without the flag nothing changes, and records go to stdout ([`wye serve`](docs/operations.md#commands)).
- `wye service install` runs the gateway with `--usage-log ~/.wye/usage.jsonl`, so the service's usage log is rotated, and sends stdout with stderr to the message log `wye.log`.
- `wye report` takes several usage logs (`cat replica-*.jsonl | wye report -` still works), and with none reads `~/.wye/usage.jsonl` with its rotated files, oldest first.
- `wye report --since` keeps records from a time back from now (`30m`, `24h`, `7d`) or a UTC date (`2026-11-01`); the first line names the window and counts the records before it. An end to the window is a filter in a pipe (`jq`).
- Usage records, and the `usage_log_dropped` and `otlp_dropped` events, carry `"v":2` after `event`, the record format's version, raised by any change that renames a field or changes its meaning. `wye report` reads lines without it, and the `"v":1` lines earlier builds of `main` wrote; OTLP is unchanged.
- Breaking, records: a usage record's `path` is `endpoint`, the glossary's name, as in `wye explain --endpoint` and a policy test's `endpoint`. OTLP keeps OpenTelemetry's `http.route`. `wye report` reads logs of every version alike.
- Breaking, records: an upstream without an `id` is named by its provider (`anthropic`, `openai`, `bedrock`, `claude-platform-aws`), so every forwarded request's record carries `upstream`, OTLP logs, spans, and metrics carry `wye.upstream`, and `pricing.prices.upstreams` and `wye report`'s upstream table work with a route's only upstream. An `id` is required only when two upstreams share a provider, and must still be unique across all upstreams, so a lone OpenAI upstream without an id now clashes with a Claude upstream whose `id` is `openai`. Config errors, `wye doctor`, `wye policy-diff`, and startup name an upstream by its id (`upstreams "anthropic": ...`); the `routes.claude.upstreams[0]` form is gone. `wye explain` shows the selection step for a route's only upstream too.
- Config: `[server]` is optional, and `listen` defaults to `127.0.0.1:8080`, the gateway `wye claude`, `wye codex`, and `wye probe` use without `--url` or `$WYE_URL`. `base_url` defaults to `https://api.anthropic.com` for provider `anthropic` and `https://api.openai.com` for `openai`; `bedrock` and `claude-platform-aws` still need one, since it names the region. `wye init` leaves out both, and the upstreams' ids (`--shared` still writes `listen = "0.0.0.0:8080"`).
- Breaking, config: one shape for each kind of value, and no field for a bound Wye can fix or derive; no aliases, so an old field fails at startup with an unknown-field error. Secrets: `provider_key_env = "X"` → `provider_key = { env = "X" }`, `provider_key_file = "p"` → `provider_key = { file = "p" }`, `[cache_diagnostics] hash_key_env` → `hash_key = { env = "..." }` or `{ file = "..." }`, `[telemetry] otlp_headers_env` → `otlp_headers = { env = "..." }` or `{ file = "..." }`; files are relative to the config, as before, and `wye service` now runs a config whose hash key and OTLP headers come from files (it still refuses environment-held secrets, naming the file form). Durations are strings in the command line's syntax (`"30s"`, `"10m"`, `"8h"`, `"7d"`) with the same limits, renamed `connect_timeout_secs` → `connect_timeout`, `response_header_timeout_secs` → `response_header_timeout`, `stream_idle_timeout_secs` → `stream_idle_timeout`, `[server] drain_delay_secs` → `drain_delay`, `shutdown_grace_secs` → `shutdown_grace`, `[auth] max_gateway_token_ttl_secs` → `max_gateway_token_ttl`; `--ttl` and `--since` read the same syntax, which needs a unit (`--ttl 90` is refused; `90s`). Failover: the route fields `failover` and `failover_max_body_bytes` → removed; a route of two or more upstreams always fails over on `429`, `529`, and `connect` for bodies up to 8 MiB, and a route of one cannot. Bounds ([local resource bounds](docs/policy.md#local-resource-bounds)): `[server] max_total_held_bytes` → twice `max_request_body_bytes` (64 MiB by default), `max_total_kept_bytes` → fixed at 256 MiB, `max_connections` → twice `max_concurrent_requests`, `client_write_timeout_secs` → fixed at 60 s. Wye tokens: `[auth] issuer` → removed (`iss` is always `wye`), `[[auth.signing_keys]]` with `id` and `ed25519_public_key` → `[auth] signing_keys = ["<public key>", ...]`; a token's `kid` is its key's RFC 7638 JWK thumbprint, which `wye token issue` writes, `wye explain` shows, and `wye policy-diff` compares keys by, so tokens issued before this change must be reissued. Identity providers are unchanged.
- Breaking, config: routes are derived from one list of upstreams, with no aliases. `[[routes.claude.upstreams]]` and `[[routes.openai.upstreams]]` → `[[upstreams]]`, and `[routes.claude]` and `[routes.openai]` are removed. An upstream's `provider` decides its route (`anthropic`, the default, `claude-platform-aws`, and `bedrock` serve Messages; `openai` serves Responses and Chat Completions), so an OpenAI upstream now says `provider = "openai"`. `select = "cache_affine"` → the default; `select = "ordered"` → `standby = true` on every upstream but the first. The upstreams of a route that are not standby share its sessions by weight, and standbys take a request only when failover has moved past all of those, in config order. A standby takes no `weight`, and a route needs one upstream that is not standby. Still at most 16 upstreams per route, ids unique across all of them. Errors name an entry as `upstreams "a": base_url ...`; `wye explain` reports `cache affinity by session id` (was `cache_affine by session id`), `the only one not standby` (was `ordered: the first in config`), and marks standbys in the failover order; `wye policy-diff` names upstreams the same way and lists a provider that moves an upstream to another route, and a standby added or dropped. The 404 for an API with no route says what to add (`an [[upstreams]] entry with provider = "openai"`).
- Config: caller-credential passthrough on the OpenAI route, where `forward_caller_credential = true` on its only upstream (loopback only, no `[auth]`, as on the Claude route) forwards each caller's own OpenAI API key. `wye init --openai` writes it in the default setup instead of `openai.key` (`--provider-key` still writes `openai.key`, `--shared` `OPENAI_API_KEY`). Without a gateway token, `wye codex` sends your `OPENAI_API_KEY` to a gateway on this machine. A ChatGPT sign-in cannot pass through a gateway, so Codex needs an API key ([`wye codex`](docs/operations.md#agent-wrapper)).
- Config: `[pricing] version` is optional. Without it, records carry 16 hex digits of a hash of the parsed price entries, the same on every replica and run, unchanged by comments and layout ([price table](docs/policy.md#price-table)).
- `wye init`'s next steps for this machine (the default and `--provider-key`) no longer start with `wye doctor`, since `wye service install` checks the config itself. `--shared` keeps it.
- `wye report` prints the skipped-line count, the cache-miss section, and the table by upstream only when they say something (lines were skipped, a cache missed, two or more upstreams served).
- Breaking, CLI: `wye validate` is removed. `wye policy-test` now reads the identity providers' key sets too, as the gateway does at startup, so CI that ran both runs `policy-test` alone, still without credentials; a key set missing fails it.
- Breaking, CLI: `wye init --shared` writes the config `-c` names, else `$WYE_CONFIG`, else `$WYE_HOME/wye.toml`, as every command does, instead of `./wye.toml`; in a config repository, `wye init --shared -c wye.toml`.
- Breaking, CLI: `wye service` no longer recognizes a service definition written by 0.1.0-rc.2 or earlier (stdout appended to `usage.jsonl`, no `--usage-log`). `status`, `restart`, and `uninstall` call it someone else's. Run `wye service install` once to replace it. `restart` still rewrites a definition of this form when a new `wye` path or the config's drain and grace call for it.
- Security: every credential Wye sends upstream, including a caller's own in passthrough, is marked never-indexed for HTTP/2 header compression, so it stays out of the compression table that requests from other callers on the same connection share. Wye's own provider keys already were.
- Benchmarks: a reference environment for published numbers (`bench/reference/`), where `run.sh`, started by hand, benchmarks a pushed commit against every competitor at pinned, checksum-verified versions on a fresh `c7i.4xlarge`, with the gateway pinned to two physical cores (`WYE_BENCH_GATEWAY_CPUS`), and always deletes the instance ([reference environment](docs/benchmarks.md#reference-environment)).
- Published benchmark numbers now come from three reference-environment runs of one commit on fresh `c7i.4xlarge` hosts, with every competitor in the same session, instead of the development machine; `bench/baseline.json` is their median, and `docs/benchmarks.md` sets each competitor's own claim beside the number measured for it ([results](docs/benchmarks.md#results)).
- `wye-bench alternate` and `wye-bench gate` now run the alternating rounds and the gate's rerun rule that `scripts/bench.sh` ran, with the same commands and verdicts.
- The `Dockerfile` keeps Cargo's downloads and `target/` in BuildKit cache mounts, so a rebuild after a source change compiles only Wye, and builds without line tables, which the image strips anyway.

### Security

- `SECURITY.md` says how to report a vulnerability privately, what a running gateway holds and reaches, and how releases are built and verified.
- The install command in the README and the guide builds the latest release tag (`--tag v0.1.0-rc.2`) instead of `main`, and both show how to check a release archive with `gh attestation verify <archive> --repo askrid/wye`.
- A version tag publishes a release only if `ci` passed on that commit on `main`; a tag on a red or unmerged commit publishes nothing.
- The release workflow pins every action to a commit SHA, like the other workflows, and the `Dockerfile` pins its base images by digest.
- `cargo deny check advisories` runs weekly, so an advisory against a locked dependency is caught between changes.
- Breaking: a gateway without `[auth]` refuses, with `403 permission_error`, a request whose `Host` is not `localhost`, `127.0.0.1`, or `[::1]` (with or without a port), or that carries `Origin` or a `Sec-Fetch-Site` other than `none`. A web page could otherwise reach the loopback port through DNS rebinding, spend the provider key Wye holds or the caller's forwarded login, and read the replies. Claude Code, Codex, and the SDKs send none of these; a client that names the gateway by another host name (an `/etc/hosts` alias) must use `localhost`. `/healthz` and `/readyz` still answer anyone. `wye explain` reports the refusal and takes request headers with `--header` (`-H`).
- Breaking: config refuses a `[telemetry] otlp_endpoint` over plain http to a host other than this machine, as it refuses such a `base_url`, since OTLP headers (an API key) and records would cross the network in the clear. Use https, or a collector on loopback; `examples/team` and `examples/app` now send to a collector beside the gateway (`http://localhost:4318`).
- Open client connections, idle ones included, are bounded at twice `[server] max_concurrent_requests` (20,000 by default). At the limit Wye stops accepting until one closes, and new connections wait in the kernel's listen queue. That needs an open-file limit of about twice as many (a client and an upstream connection each). `wye service install` now sets 65536 in the LaunchAgent and the systemd unit, where launchd would start the gateway with 256 and systemd with 1024. `wye serve` run by hand or in a container keeps the limit it inherits (`ulimit -n`).
- With a provider key, responses no longer carry the provider's `anthropic-organization-id`, `openai-organization`, or `openai-project`, which named the operator's account to gateway-token holders. Passthrough keeps them, since the account is the caller's.
- Breaking: `[auth] max_gateway_token_ttl` is at most `"30d"`; a config above that fails at startup. `wye init --shared`'s next steps say to keep the signing key off the hosts that serve.
- `wye doctor` fails when a secret file, or the signing key in `~/.wye/signing.key`, can be opened by group or others, and names the `chmod 600` to run; `serve` warns of such a secret file and starts.
- The docs say that `wye claude` passes a gateway token as `ANTHROPIC_AUTH_TOKEN`, which every tool Claude Code runs inherits, and point to `apiKeyHelper` to keep it out of the environment; and that a loopback gateway without `[auth]` serves every user of its machine.

## 0.1.0-rc.2

Names settle. Config fields, record values, metrics, and CLI flags now use the glossary's terms, and the Claude route has one form. Many changes are breaking (marked below); a 0.1.0-rc.1 config needs the renames listed under "Breaking, config". `wye init` writes sample policy tests, and every command run with no arguments says what to run next.

- License: MIT, instead of WTFPL.
- Breaking: `wye init --api-key` is now `--provider-key`, and `--team` is now `--shared`. The flags name the two choices a [setup](docs/glossary.md#the-product) makes. `--shared` with `--provider-key` is no longer an error, since a shared gateway always holds the provider key.
- Examples, one directory per use: `examples/developer/` (was `examples/subscription.toml`), `examples/team/` (developers through SSO, CI through GitHub Actions tokens, two keys with failover), and `examples/app/` (a gateway token per service, aliases with a canary, a second provider for failover, OpenAI), the last two with policy tests that the test suite runs. `examples/policy-tests/` is gone; its config trusted a public test key.
- The sample price tables (README, `docs/policy.md`, `examples/wye.toml`) priced cache reads on Opus 5.5 and Sonnet 5.5 at 0.1 times input; Anthropic charges 0.05 times. A table copied from them counts cache reads at twice their cost, so set `cache_read = "0.20"` for Opus 5.5 and `"0.10"` for Sonnet 5.5.
- `examples/wye.toml` sets the `[server]` and Claude route options live at their defaults instead of in comments, so every option is visible.
- Docs: the README says what Wye does, who it is for, how it compares with what teams expect of a gateway, and how fast it is; the guide gains how-tos for several upstreams, costs, model aliases and upgrades, and an OpenTelemetry backend.
- `wye-bench --agentgateway` runs the benchmark through agentgateway; results in `docs/benchmarks.md`.
- Fix: under an output-token ceiling, a body with a second JSON value after the object (`{...}{"max_output_tokens":10}`) is refused. It passed on the OpenAI routes, and a provider whose parser reads only the first value would have seen no ceiling.
- Fix: a model name longer than 128 bytes from the provider is no longer kept in records and metrics (Messages and Chat Completions streams).
- Fix: with OTLP on, a usage log whose reader stalls keeps as many records as without OTLP, and shutdown exports the final metrics even while the usage log is blocked.
- `wye report` keeps each count on the line of its name when it wraps.
- A body sent in chunks so small that it alone passes `max_total_held_bytes` gets `413` instead of the retryable `529` (`503` on the OpenAI APIs), which no retry could clear.
- The refusal of an output-token value over the ceiling says `exceeds the output-token ceiling of N`; it said `this gateway token's limit` even when the ceiling came from `[auth] max_output_tokens` alone. `wye explain` shows `(ceiling N)`.
- Breaking, config: keys renamed so each names what it holds, with no aliases; a config with an old name fails at startup with an unknown-field error. `api_key_env` → `provider_key_env` and `api_key_file` → `provider_key_file` (in every upstream); `[[auth.issuers]]` → `[[auth.identity_providers]]` (and its `grants`); `[[auth.keys]]` → `[[auth.signing_keys]]`; `[auth] max_token_ttl_secs` → `max_gateway_token_ttl_secs`; `[server] max_held_request_bytes` → `max_total_held_bytes`; `[[pricing.models]]` → `[[pricing.prices]]` (and its `tiers`). The route option `failover_max_held_bytes` is now `[server] max_total_kept_bytes`. It always bounded kept bodies across the whole process, so it is set once there, with the same default (256 MiB).
- Breaking, config: `[upstream]` is removed, with no alias; the Claude route has one form, `[[routes.claude.upstreams]]` entries with optional `[routes.claude]` fields, and a config with `[upstream]` fails at startup with an unknown-field error. Move its fields into one `[[routes.claude.upstreams]]` entry. `id` is optional when a route has one upstream (its records then carry no `upstream`, as before), and `forward_caller_credential = true` moves there, allowed on the Claude route's only upstream, still loopback only and not with `[auth]`.
- Config errors name the field as the config writes it, with `routes.claude.upstreams "a": provider_key_env` for a route's upstream, `routes.claude.upstreams[0]: base_url` for a route's only upstream written without an id, and `routes.openai.select` for a route's own options; a file that fails to load at startup is named the same way.
- Breaking, records: what Wye emits is renamed, with no aliases. Usage records: the `outcome` `gateway_error`, which covered Wye's refusals, upstreams that gave no response, and Wye's own faults, splits into `refused` (Wye's refusal), `upstream_error` (Wye's `502` or `504`), and `gateway_error` (Wye's own fault only); `failed` → `truncated`; `headers_ms` → `response_headers_ms`; `context_compacted` → `after_compaction`; the `usage_status` `not_observed` → `none`; each `failovers` entry's `status` or `error` → `reason` (`429`, `529`, or `connect`); `prompt` → `prompt_hashes`; the `usage_log_dropped` event's `count` → `records`, as in `otlp_dropped`. New: `upstream_error` says why an upstream gave no usable response (`connect`, `timeout`, or `reset`), and `wye report` counts it. OTLP logs and spans: `gen_ai.system` → `gen_ai.provider.name`, now the provider of the upstream that served the request (`aws.bedrock` for Bedrock); `wye.requested_model` → `gen_ai.request.model`; `wye.headers_ms` → `wye.response_headers_ms`; `wye.context_compacted` → `wye.after_compaction`; `wye.prompt` → `wye.prompt_hashes`; new `wye.upstream_error`; tool spans `tool <name>` → `execute_tool <name>`, with `gen_ai.operation.name`; a `refused` request's span leaves its status unset instead of `ERROR`. Metrics: `wye.telemetry.lost` → `wye.records.dropped`; in `wye.failovers`, `wye.upstream` → `wye.failover.upstream`, unit `{request}` → `{failover}`; `wye.upgrade.issues` unit `{request}` → `{issue}`. Client errors: an upstream's header timeout (`504`) is `timeout_error` (was `api_error`), and a client body stalled during the hold (`408`) is `invalid_request_error` (was `timeout_error`). `wye report` still reads older logs.
- `wye service restart` rewrites the service definition when this `wye` or the config's `drain_delay_secs` and `shutdown_grace_secs` call for a new one, and has the service manager load it; a restart used to keep the old stop timeout.
- Breaking, CLI: names say what they hold, with no aliases. The signing key `~/.wye/issuer.key` is `~/.wye/signing.key` (`mv ~/.wye/issuer.key ~/.wye/signing.key` keeps yours); `wye token issue --key` is `--signing-key`; `wye explain --path` is `--endpoint`, and a policy test's `path` is `endpoint`. Output: `wye explain`'s steps `token:` → `gateway token:` (with `key id`), `route:` → `selection:`, and `provider key: the caller's own` → `credential: the caller's own (passthrough)`, and a path it does not serve reads `not an endpoint Wye serves`; `wye report`'s `(no hint)` class → `(unclassified)`, and its time columns read `model` and `tools` under `time`; `wye service`'s `Log` and `Errors` → `Usage log` and `Messages`; `wye policy-diff` names a `provider key` (not the operator's key), a `gateway token`, and `Wye tokens`; `wye doctor` checks a config's secrets, files, and upstreams.
- `wye init` also writes `policy-tests/` next to the config, with sample requests and the decisions the config it wrote makes (with `--shared`, a request with a gateway token that forwards and one without, refused with `401`), so `wye policy-test` passes right after `wye init`. It never writes over a file. Run with no argument, each command does what its name says or fails with one line that says what to run next. `wye explain` names a sample request, `wye policy-test` without cases says how to add them, `wye token issue` and `wye policy-diff` show an example, `wye claude`, `wye codex`, and `wye probe` say to run `wye init` when nothing answers and there is no config, `wye token issue` without a signing key says how to make one, and `wye token keygen` refuses to replace the key `wye token issue` signs with. `wye service status` shows the message log too.
- Links that the CLI prints or writes (the config `wye init` writes, its deployment step, `wye service`'s advice on secrets) point at this version's release tag instead of `main`, so they describe the config keys and commands of the `wye` that printed them.

## 0.1.0-rc.1

A prerelease, to prove the release pipeline. Wye is a working prototype, tested and benchmarked on one machine and used with Claude Code through a claude.ai subscription. Expect the config format to change before 1.0. `wye service` has not run under systemd on a real Linux machine.

What is in it:

- Anthropic Messages (`/v1/messages`, `count_tokens`), OpenAI Responses, and OpenAI Chat Completions, forwarded byte for byte, streams relayed event by event.
- Routes with several upstreams. Each Claude Code session stays on one upstream (weighted rendezvous hashing on the session id). Failover on `429`, `529`, or a connection refused or cut before the request body was delivered, and never after the first response byte.
- Providers for Claude: Anthropic, Claude Platform on AWS, and Amazon Bedrock, with API keys.
- Gateway tokens: Wye's own Ed25519 tokens, or identity-provider tokens (RS256, ES256, EdDSA) with keys pinned in config. Model permissions and output-token ceilings, which a gateway token can narrow but never widen.
- Model aliases with per-subject rollout, and upgrade checks that report which requests a target model would reject.
- Usage records per request (tokens, cost, cache hits and misses, session, subagent, request class, tool calls and time), OTLP logs, traces, and metrics, and optional cache-miss diagnostics.
- Cost from a price table in config, in exact integer arithmetic.
- Commands: `init`, `serve`, `validate`, `doctor`, `explain`, `policy-test`, `policy-diff`, `report`, `probe`, `claude`, `codex`, and `token`, each with `--help`. A user's files live in `~/.wye`, and a command reads `~/.wye/wye.toml` unless told otherwise (`-c`, `$WYE_CONFIG`), never a config it merely finds in the working directory. `wye claude` turns on Claude Code's gateway hints (request class, prompt id, tool times), and `wye claude --bg` starts background sessions that go through the gateway too.
- `wye service install`, `status`, `restart`, and `uninstall`: the gateway as a LaunchAgent (macOS) or systemd user unit (Linux), shown before it is written and checked before it starts.
- Release archives for Linux and macOS (x86_64, arm64) with checksums and build provenance attestations.

Not yet checked against the real services:

- Bedrock and Claude Platform on AWS were built from the providers' documentation and tested against mocks. Bedrock's API key header in particular is unconfirmed (`x-api-key` is sent).
- Codex support was built from Codex's source and tests, not from a real session.

Known limits:

- No Windows build, no published container image, no Vertex AI, no AWS SigV4.
- Provider keys are read at startup; short-lived keys need a restart to refresh.
- No cumulative budgets or rate limits, by design. Those stay with the provider.
- Model permissions read the request's top-level `model`; a model named inside the body (an OpenAI `image_generation` tool's) is not checked.
- Findings from review rounds that are still open are listed in docs/roadmap.md, "Open findings".
